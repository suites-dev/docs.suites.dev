# Technical Documentation Guide

Use this skill to keep developer documentation useful during real work rather
than treating it as a one-time publication artifact.

Before substantial writing or structural review, read the
[source guide](./technical-docs-guide.md) completely. Treat it as methodology
and supporting evidence, not as product authority.

Apply these decisions:

- Identify the reader, their task, and the page type before choosing structure.
- Keep explanation, tutorial, how-to, and reference responsibilities distinct.
- Prefer concise examples and maintained evidence over unsupported abstraction.
- Separate generated or mechanically verified facts from prose that requires
  product judgment.
- Preserve explicit user direction and repository product boundaries when they
  differ from generic guidance in the source.
