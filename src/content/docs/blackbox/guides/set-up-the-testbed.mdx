Blackbox adapts to the way you already start your system. The source strategy changes provisioning; the runner, capture protocol, evidence format, and analyzers stay the same.

```text
Compose ───────┐
Dockerfile ────┤
dist folders ──┤
host command ──┼──> isolation cell -> capture -> sealed evidence -> analysis
running SUT ───┤
custom setup ──┘
```

## Choose From What You Already Have

| Starting point                     | Source kind  | Lifecycle owner  | Quickstart role                         | Guide                                                                             |
| ---------------------------------- | ------------ | ---------------- | --------------------------------------- | --------------------------------------------------------------------------------- |
| A normal start command             | `command`    | Blackbox         | Step 2 provisioning                     | [Run a Host Command](/docs/blackbox/guides/run-a-host-command)                    |
| One or more Compose files          | `compose`    | Blackbox         | Replace Step 2 provisioning             | [Use an Existing Compose Project](/docs/blackbox/guides/use-existing-compose)     |
| A Dockerfile                       | `dockerfile` | Blackbox         | Replace Step 2 provisioning             | [Build From a Dockerfile](/docs/blackbox/guides/build-from-dockerfile)            |
| Compiled `dist/` folders           | `artifacts`  | Blackbox         | Replace Step 2 provisioning             | [Run Compiled Artifacts](/docs/blackbox/guides/run-compiled-artifacts)            |
| A process you already run          | `external`   | You              | Replace Step 2 provisioning             | [Connect an External SUT](/docs/blackbox/guides/connect-external-sut)             |
| Testcontainers or another platform | `custom`     | Your provisioner | Replace Step 2 provisioning             | [Use a Custom Provisioner](/docs/blackbox/guides/use-custom-provisioner)          |
| Parallel or unusual cell lifecycle | —            | Varies           | Step 2 deep dive, then rejoin at Step 3 | [Configure Isolation](/docs/blackbox/guides/playwright-isolation-and-parallelism) |
| Nonstandard compiled layouts       | —            | Varies           | Step 2 deep dive, then rejoin at Step 3 | [Configure Source Maps](/docs/blackbox/guides/source-maps-and-service-layouts)    |

Use `command` for the first flow when it represents your application honestly. Choose Compose when correctness depends on databases, caches, queues, or other mutable services that must be isolated together.

## One Configuration, Not Separate Modes

All strategies live in `blackbox.config.ts`:

```ts
import { defineBlackboxConfig } from "@suites/blackbox";

export default defineBlackboxConfig({
  sut: {
    source: { kind: "command" /* source-specific fields */ },
    services: {
      /* endpoints, environment, capture, layout */
    },
  },
  lifecycle: { ownership: "blackbox" },
  isolation: { scope: "flow" },
  runner: { kind: "playwright", config: "playwright.config.ts" },
  evidence: { dir: ".blackbox/evidence" },
  analysis: { effects: "check" },
});
```

The configuration separates decisions that often change independently:

| Concern        | What it controls                                                                  |
| -------------- | --------------------------------------------------------------------------------- |
| `sut.source`   | How Blackbox obtains and starts the system                                        |
| `sut.services` | Service identity, endpoints, environment, language capture, and executable layout |
| `lifecycle`    | Whether Blackbox or the user starts and stops the SUT                             |
| `isolation`    | Whether a cell belongs to a flow, worker, or test                                 |
| `runner`       | Which native test runner opens and closes attempts                                |
| `evidence`     | Where sealed runs are retained                                                    |
| `analysis`     | Which effect and ODC policies gate the run                                        |

## What Blackbox Infers

Blackbox assigns run, cell, worker, attempt, retry, service, and instance identities. It also supplies the sidecar connection, injects language capture, discovers source maps, and chooses analyzers from declared capture capabilities.

You supply:

- The command, Compose file, Dockerfile, artifact folder, endpoint, or custom provisioner you already use.
- The services that belong to the SUT.
- Readiness only when Blackbox cannot discover it.
- Selected environment inputs and secrets.
- Nonstandard artifact boundaries.
- Reset behavior for mutable state Blackbox cannot reconstruct safely.
- Effect contracts and analysis policy.

## Isolation Includes Mutable Dependencies

An isolated API process sharing one database with another flow is not an isolated system. Include databases, queues, caches, object stores, background workers, and mutable mock servers inside the cell or reset them before each independent attempt.

Keep the Playwright adapter and project fixture from Quickstart Step 2 for every source strategy. After the selected guide passes its validation command, rejoin at [Step 3: Run and Inspect Evidence](/docs/blackbox/quickstart/add-runtime-evidence).
