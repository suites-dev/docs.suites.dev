Choose the setup input before Blackbox allocates a runtime attempt. The input determines which services, networks, storage, identities, and lifecycle boundaries the sandbox provider owns.

## Setup Decision

| Application input                             | Status         | Use                                         |
| --------------------------------------------- | -------------- | ------------------------------------------- |
| Current development Compose project           | Supported path | Use the project's existing Compose topology |
| Dockerfile and build context                  | Unsupported    | Read the future workflow only               |
| Compiled artifact directory and start command | Unsupported    | Read the future workflow only               |

Unsupported inputs fail explicitly before Blackbox claims assurance. They never fall back to Compose or receive an equivalence claim.

## Use the Compose Path

Choose Compose when the project already defines the application and its real dependencies together.

The sandbox provider must:

- Own the selected service, network, storage, and lifecycle boundaries.
- Produce the expected participant inventory deterministically.
- Bind service and artifact identity to one sandbox lease.
- Inject generated observation and control configuration.
- Disclose access to unowned resources.
- Prove teardown or quarantine the lease.

[Use an Existing Compose Project](/docs/blackbox/guides/use-existing-compose) for the detailed workflow.

## Summary

- Use the existing Compose topology for the accepted setup path.
- Treat every provider and topology combination as its own support cell.
- Stop on ambiguous ownership or unsupported input instead of weakening assurance.
