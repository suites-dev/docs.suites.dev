Use this guide after a Playwright system flow passes and you want readable Gherkin for review, traceability, or agent context. Gherkin is optional for runtime verification; it does not replace the executable test or runtime evidence.

If you have no system test yet, use [Quickstart Step 1B](/docs/blackbox/quickstart/start-without-test) instead. That route starts from plain-language intent and creates the test shell before connecting the application.

If you want a coding agent to review the generated Gherkin, [install the Blackbox Skills first](/docs/blackbox/guides/agent-skills). The deterministic CLI steps work without a Skill.

## 1. Discover Existing Flows

```bash
pnpm exec blackbox suites discover ./e2e --json
```

Resolve missing IDs, duplicate IDs, multiple flows in one file, and mismatched file stems before continuing.

## 2. Emit Baseline Gherkin

```bash
pnpm exec blackbox features emit ./e2e --out ./baseline --json
```

The baseline represents executable structure. It cannot recover product intent that is absent from the test.

Ask `$blackbox-gherkin` to review the baseline against the suite and known behavior. Move the accepted feature beside the effect contract:

```text
e2e/features/subscribe-user.feature
e2e/features/subscribe-user.effects.yaml
e2e/subscribe-user.system.test.ts
```

## 3. Review the Feature

```gherkin
@flow:subscribe-user
Feature: Subscribe a user

  Scenario: Unknown user is rejected
    When the client subscribes an unknown user
    Then the response status is 404
```

Keep the same `@flow:` token in the feature and Playwright test. Improve wording, but do not invent unverified behavior merely to make the scenario look complete.

## 4. Align and Check

Preview structural alignment:

```bash
pnpm exec blackbox suites align \
  e2e/features/subscribe-user.feature \
  --suite e2e/subscribe-user.system.test.ts \
  --json
```

Apply the reviewed transformation:

```bash
pnpm exec blackbox suites align \
  e2e/features/subscribe-user.feature \
  --suite e2e/subscribe-user.system.test.ts \
  --write \
  --json
```

The aligned Playwright suite retains its tagged native structure and places accepted clauses in `test.step()` blocks. Application actions and assertions remain project-owned.

```bash
pnpm exec blackbox suites check ./e2e --json
```

## 5. Add Requirements Only When Needed

If the feature binds to `@requirement:<id>` tags, validate the requirement corpus and its relationships:

```bash
pnpm exec blackbox requirements validate ./requirements --json
pnpm exec blackbox features check ./e2e/features --requirements ./requirements --json
pnpm exec blackbox requirements check ./requirements --tests ./e2e --json
pnpm exec blackbox requirements drift ./requirements --tests ./e2e --json
```

## Result

You have a passing native flow and a reviewed readable projection joined by one stable ID. Run `features check` and `suites check` whenever either artifact changes so the documentation stays tied to executable behavior.
