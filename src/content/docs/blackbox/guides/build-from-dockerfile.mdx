:::note Unsupported Setup Input
Dockerfile and build-context input is not supported. Blackbox returns a structured `unsupported` result before runtime assurance begins.
:::

This future path is intended for a service that has a repeatable Dockerfile but no Compose topology.

## Intended Workflow

When certified, the workflow will:

1. Accept an explicit Dockerfile and build context.
2. Resolve the exact platform artifact produced by the build.
3. Allocate an owned network, storage, service, and lifecycle boundary.
4. Inject generated observation and control configuration.
5. Admit participants and capabilities before starting the selected test.
6. Bind evidence to the exact built artifact and sandbox lease.
7. Prove teardown or quarantine the lease.

## What This Page Does Not Promise

This setup is not equivalent to the supported Compose path. Blackbox does not silently translate it into Compose or fall back to weaker capture.

Public configuration syntax will be documented only after the exact Dockerfile cell completes certification.

## Use the Supported Path

Use [an existing Compose project](/docs/blackbox/guides/use-existing-compose) for the current setup workflow.
