---
title: "Build From a Dockerfile"
description: "Build an ephemeral captured SUT from a Dockerfile without maintaining a separate Blackbox image."
keywords: ["Blackbox Dockerfile", "container system test", "Node capture"]
---

Use a Dockerfile source when one service already has a repeatable container build but the project does not need a full Compose topology.

Complete [Quickstart Step 1A](/docs/blackbox/quickstart/build-behavioral-harness) or [Step 1B](/docs/blackbox/guides/turn-requirements-into-system-test) first. This setup replaces sections 1 and 2 of Step 2. After configuring the Dockerfile, return to the common Playwright integration in section 3.

## Configure the Build

```ts title="blackbox.config.ts"
import { defineBlackboxConfig } from "@suites/blackbox";

export default defineBlackboxConfig({
  sut: {
    source: {
      kind: "dockerfile",
      file: "Dockerfile",
      context: ".",
    },
    services: {
      api: {
        containerPort: 3000,
        readiness: { kind: "http", path: "/health" },
        environment: {
          files: [".env.test"],
          passthrough: [],
          values: { NODE_ENV: "test" },
        },
        capture: { language: "node" },
        layout: {
          artifactRoot: "dist",
          sourceMaps: "discover",
        },
      },
    },
  },
  lifecycle: { ownership: "blackbox" },
  isolation: { scope: "flow" },
  runner: { kind: "playwright", config: "playwright.config.ts" },
  evidence: { dir: ".blackbox/evidence" },
  analysis: { effects: "check" },
});
```

Blackbox builds the declared target, attaches capture in an ephemeral derived layer, maps the application port, and starts one service instance per cell.

## Preserve the Application Image

The project Dockerfile remains application-owned. Blackbox does not require production code imports or permanent test instrumentation in the published image.

Keep executable JavaScript and its source maps in the image. Offline analysis uses the exact bytes captured from the running service, not a separately rebuilt host copy.

## Handle Dependencies

A Dockerfile source isolates the declared service. If the application depends on PostgreSQL, Redis, queues, or workers, either:

- move to a Compose source that includes them;
- point the cell at independently isolated dependencies; or
- use a custom provisioner that owns the complete topology.

Do not treat a fresh application container connected to shared mutable state as full flow isolation.

## Validate the Cell

```bash
pnpm exec blackbox doctor --json
```

Expected result: Blackbox resolves the Dockerfile, build context, service port, capture capability, and readiness plan without a configuration error.
