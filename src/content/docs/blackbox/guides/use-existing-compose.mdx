Use this guide when your team already runs the application and its dependencies with Docker Compose.

## Before You Begin

You need:

- A human-approved behavioral contract with one Playwright realization.
- A Compose project that includes the application and dependencies the test reaches.
- Declared observation and completion capabilities for the selected effect claims.

Complete [Get Started](/docs/blackbox/quickstart/) or [Start From an Existing System or E2E Test](/docs/blackbox/quickstart/build-behavioral-harness) first.

## 1. Identify the Owned Topology

Start with the services the selected system test can reach:

```yaml title="compose.yaml, shortened"
services:
  product-service:
    build: ./services/product
    depends_on: [postgres, redis]
  postgres:
    image: postgres
  redis:
    image: redis
```

Document every database, API, queue, cache, volume, or network outside this project. Blackbox cannot present an unowned resource as isolated.

## 2. Make Participation Deterministic

Provide an exact expected participant inventory before capture starts. Each required participant must identify itself, advertise its admitted capabilities, and confirm capture-protocol readiness.

Resolve ambiguous service discovery before you run the test.

## 3. Keep Telemetry and Control Separate

Allow the sandbox provider to inject generated OTLP observation configuration and separate control authorization. Do not reuse public correlation IDs as credentials or expose internal transport variables as project API.

## 4. Run One Fresh Attempt

Run the selected Playwright case through the project's declared Blackbox execution entrypoint.

Blackbox allocates a fresh lease, starts the selected topology, waits for required participants, captures the attempt, and tears the topology down afterward. If teardown cannot be established, Blackbox quarantines the lease instead of reusing uncertain state.

## 5. Verify the Result

For the checkout example, read the native result and effect finding separately:

```text
Native result      checkout returned 201
Runtime evidence   POST /payments/charges × 2
Behavioral claim   at most 1 charge request
Finding            violated
```

Confirm that:

- The native Playwright result is visible.
- Required participants and capabilities were admitted.
- Evidence belongs to one attempt and one capture window.
- The finding states its exact evidence scope.

After the implementation is repaired, use the same declared execution entrypoint again. The rerun receives fresh evidence and preserves the earlier attempt in history.

## Summary

- Keep the existing Compose topology as the source of the application shape.
- Make owned and unowned resources explicit.
- Run each independent attempt with fresh evidence and teardown.
- Read native assertions and effect findings as separate results.
