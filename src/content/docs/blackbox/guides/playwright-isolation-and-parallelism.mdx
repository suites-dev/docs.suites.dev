Choose the topology from the behavior the case requires. Playwright scheduling does not define Blackbox evidence boundaries.

## Choose a Topology

| Need                                     | Topology                                | Evidence rule                                                                       |
| ---------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------- |
| Cases do not share state                 | Independent attempts                    | Fresh lease, runtime identity, capture, evidence, and teardown per physical attempt |
| Cases must share declared state in order | Ordered group                           | One fresh group lease, separate member attempts and evidence                        |
| Two or more cases must be compared       | Explicit comparison                     | Exact named members and controlled dimension, no evidence aggregation               |
| Operations must overlap                  | Typed parallel branches inside one case | One case owns the synchronization contract                                          |

## Run Independent Cases

Serial and parallel Playwright workers follow the same assurance rule. Independent attempts never share evidence or runtime assurance state.

A teardown failure quarantines that lease. It cannot become the next worker's starting state.

## Declare Ordered State

Use an ordered group only when later cases depend on state produced earlier. Declare contiguous member order, shared domains, transfer attestations, stop-on-failure behavior, and final cleanup.

Members remain separately verdictable. If one member fails, later members become `not-executed`.

## Retry From a Fresh Baseline

Every retry receives fresh runtime and evidence identity. An ordered-group retry restarts the full group on a new sandbox lease, not only the failed member.

Blackbox keeps earlier attempts and outcomes. A favorable retry cannot replace or hide them.

## Compare Without Aggregating

A comparison names exact members, a controlled dimension, one SuitePlan revision, and an outcome-independent eligible-attempt policy.

Do not group evidence by test title, flow label, trace, file, worker, shard, or timing overlap. One member's retry cannot substitute for another member.

## Summary

- Use independent attempts by default.
- Share state only through an explicit ordered group.
- Put required concurrency inside one typed case.
- Keep every retry and comparison member's evidence separate.
