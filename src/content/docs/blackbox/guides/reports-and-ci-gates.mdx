Add Blackbox after the project can realize one accepted case locally. CI should repeat the same deterministic gates and preserve the result that explains any failure.

## 1. Validate Before Runtime Allocation

Run the canonical checks first:

```bash
blackbox features check
blackbox scenarios check
blackbox suites typecheck
```

If the project uses direct declarations without Gherkin, omit `blackbox features check`.

## 2. Run Selected Assurance Cases

A practical CI workflow then runs the selected Blackbox tests:

```bash
blackbox test
```

Each physical attempt receives fresh runtime identity, capture, evidence, and teardown. Sharding and worker placement cannot merge evidence between attempts.

## 3. Gate on the Process Exit

| Exit | CI action                                                        |
| ---- | ---------------------------------------------------------------- |
| `0`  | Continue                                                         |
| `1`  | Fail the assurance gate and route the producer-owned finding     |
| `2`  | Fix invocation, configuration, project-root, or unreadable input |

Exit `1` covers every formed non-success assurance outcome, including violated, inconclusive, unsupported, integrity-failure, and unknown finding-code cases.

## 4. Preserve Canonical Results

Store the report and exact evidence references for each attempt. Keep producer order, evidence joins, verdicts, repair routing, and prior retry history unchanged.

Color, verbosity, and retention choices may change presentation or storage, but they cannot change canonical report truth.

## 5. Keep ODC Separate

Optional Decision Coverage may run in CI, but it remains diagnostic. `not-requested`, `unavailable`, or another ODC state cannot rewrite ordinary effect findings or an otherwise successful ordinary assurance exit.

## Summary

- Fail semantic and realization problems before allocating a sandbox.
- Use exits `0`, `1`, and `2` consistently.
- Preserve evidence and prior attempts for repair and audit.
- Keep optional ODC outside the ordinary effect gate.
