CI runs the same accepted harness as local development. Add this workflow after Quickstart Step 4, when local effect policy already passes and the team has reviewed whether ODC is diagnostic or gating.

## Review Evidence Exposure First

A sealed run can contain exact executed source, source maps, configuration and policy snapshots, normalized event records, and payload-derived attributes. Treat the bundle as sensitive build output.

Before uploading it:

- Keep secrets and personal data out of test fixtures, logs, telemetry attributes, and captured request payloads.
- Inspect `config.snapshot.json`, `events.jsonl`, and the content-addressed artifact store for credentials, tokens, proprietary source, and PII.
- Perform any required redaction before data reaches Blackbox capture; artifact upload does not make unsafe evidence safe.
- Restrict artifact access to trusted repository readers and avoid exposing evidence from untrusted fork workflows.
- Choose the shortest retention period that supports failure diagnosis and your compliance obligations.

## Add the Runtime Gate

```yaml title=".github/workflows/blackbox.yml"
name: Blackbox

on:
  pull_request:
  push:
    branches: [main]

jobs:
  blackbox:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - run: pnpm exec blackbox test

      - name: Retain Blackbox evidence
        if: failure() || cancelled()
        uses: actions/upload-artifact@v4
        with:
          name: blackbox-evidence-${{ github.run_id }}
          path: .blackbox/evidence
          if-no-files-found: error
          retention-days: 7
```

`blackbox test` runs selected Playwright flows, owns managed SUT lifecycle, seals evidence, and applies the configured analysis policy. The upload step retains the complete bundle only when the job fails or is cancelled.

## Add Static Gates When You Accept Specifications

```bash
pnpm exec blackbox requirements validate ./requirements --json
pnpm exec blackbox features check ./e2e/features --requirements ./requirements --json
pnpm exec blackbox requirements check ./requirements --tests ./e2e --json
pnpm exec blackbox requirements drift ./requirements --tests ./e2e --json
pnpm exec blackbox suites check ./e2e --json
```

These commands prove structural agreement. Runtime gates prove what the executed system did.

## Choose the ODC Policy Deliberately

Effects are correctness policy. ODC is a separate decision-propagation signal.

Start by retaining ODC reports. Gate only decisions whose boundary behavior the team has explicitly chosen to protect. A masking candidate may indicate a defect, an intentionally equivalent outcome, or insufficient evidence.

## Reanalyze Without Rerunning

```bash
pnpm exec blackbox analyze --run latest
```

Offline analysis verifies the bundle and recomputes effects, source-map joining, decisions, ODC, and reports without provisioning the SUT.

Use this when:

- Reviewing a failed CI artifact locally.
- Changing an accepted analysis policy.
- Comparing analyzer versions.
- Producing another report format from the same run.

## Interpret Exit Codes

| Exit | Meaning                                                     |
| ---- | ----------------------------------------------------------- |
| `0`  | Runner, integrity, and configured analysis policies passed  |
| `1`  | Native test or behavioral finding                           |
| `2`  | Usage or configuration error                                |
| `3`  | Provisioning, capture, infrastructure, or integrity failure |

Infrastructure uncertainty is not a successful behavioral run.

## Keep Approval Outside CI

Changes to requirements, scenarios, flow IDs, assertions, effect contracts, isolation assurance, and ODC gates go through ordinary repository review. CI evaluates accepted policy; it does not rewrite policy until a run passes.

## Summary

- **Run `blackbox test` as the complete gate.**
- **Retain sealed evidence even when the job fails.**
- **Review data exposure, access, and retention before uploading evidence.**
- **Use `blackbox analyze` for reproducible offline review.**
- **Keep effect correctness and ODC policy separate.**
- **Require human review for changes to the behavioral harness.**
