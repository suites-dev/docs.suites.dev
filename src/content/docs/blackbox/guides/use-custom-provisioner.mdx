Use this path when project code already starts the application and its real dependencies with Testcontainers.

:::note Experimental Setup Path
The Testcontainers integration is **experimental**. The shape below explains the intended workflow, not a supported public configuration API.
:::

## Describe the Environment

The Testcontainers definition must identify the application, its dependencies, stable service endpoints, readiness conditions, and cleanup responsibilities.

```text title="Conceptual pseudocode"
test environment
  application: <container definition>
  dependencies: <container definitions>
  ready when: <declared readiness condition>
  stop: <owned cleanup>
```

This pseudocode is deliberately not valid Blackbox configuration. Replace it with the certified public interface when that interface is published.

## Preserve One Attempt Boundary

Start a clean environment for the selected case attempt. Every required participant must join the correct capture session before the test begins, and cleanup must not leave state for the next attempt.

Stop instead of continuing when:

- A required service does not become ready.
- A participant cannot be associated with the attempt.
- OpenTelemetry capture is incomplete for a required claim.
- Cleanup cannot establish a clean next state.

## Keep the Test Runner Separate

The environment starts the system. The Playwright test exercises the approved behavioral contract. Blackbox connects that execution to runtime evidence and findings.

Do not make Testcontainers test names, container timing, or current implementation behavior the authority for the behavioral contract.
