Imagine a system or E2E test that sees one confirmed order and passes. Blackbox checks the approved boundary claim and finds two charge requests where at most one was allowed.

Blackbox compares person-approved claims with sealed runtime evidence. Given the same approved inputs and evidence, the Analyzer returns the same finding. This is deterministic analysis, not identical distributed execution.

## Feedforward and Feedback

**Feedforward** gives the agent approved guidance before it acts. **Feedback** returns deterministic findings after the system runs.

Blackbox applies the feedforward and feedback framing from Birgitta Böckeler's <a href="https://martinfowler.com/articles/harness-engineering.html" target="_blank" rel="noopener noreferrer">Harness engineering for coding agent users</a> to behavioral verification: approved scenarios and claims guide the agent, while Analyzer findings drive repair.

## Route Feedback Without Moving Authority

Findings about the suite or implementation return to the coding agent as a repair problem. The agent reruns the same approved scenario and claims.

A proposed change to Gherkin, effect claims, or analysis policy returns to a person. Feedback can drive repair, but it cannot give the generator permission to redefine success.
