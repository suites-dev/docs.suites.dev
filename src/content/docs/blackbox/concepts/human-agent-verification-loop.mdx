## Feedforward and Feedback

**Feedforward** guides the agent before it acts. **Feedback** tells the agent what deterministic checks found afterward.

## Read the Flow

1. A person approves the Gherkin scenario and effect expectations.
2. Blackbox generates runtime bindings and `.d.ts` guidance from that accepted intent.
3. Those types guide the project-owned Playwright suite. The CLI checks it and prepares the declared run.
4. The runner executes the selected suite. Runtime captures a fresh attempt and seals the evidence.
5. The Analyzer returns integrity and effect findings.

The return path depends on the problem:

- **Suite or binding problem:** The agent repairs the project-owned suite.
- **Runtime or effect problem:** The agent repairs the implementation and reruns.
- **Target or policy change:** A person decides.

People own accepted behavior. Runtime owns evidence, and the Analyzer owns findings.
