Checkout returns `201`. OpenTelemetry traces reveal two requests to the payment service, so Blackbox can evaluate the
behavioral contract's limit of one charge request.

## From Observation to Effect

An **effect** is a normalized fact about an observed operation at a supported system boundary during one attempt.
Typical effects include an HTTP request, database operation, cache operation, or message publication.

OpenTelemetry provides observations. Blackbox uses only observations it can reliably connect to the current attempt,
then normalizes them into effects. A raw span is evidence input, not automatically an effect.

```text
OpenTelemetry observation
        ↓ admit and verify
normalized effect fact
        ↓ evaluate approved claim
finding and verdict
```

Normalization lets Blackbox compare the behavioral contract with runtime work without making the contract depend on
raw span names or trace layout. Repeated equivalent operations remain visible, so the two payment requests in this
example do not collapse into one event.

## Use a Shared Effects Catalog

The **effects catalog** names runtime operations Blackbox recognizes and describes how supported trace observations map
to those names. It describes observation, not product policy.

The public catalog syntax is not frozen. This is an illustrative view, not a supported schema:

```yaml title="Illustrative effects catalog"
effects:
  payment-charge-request:
    matches:
      boundary: http
      operation: POST
      target: /payments/charges
      serviceId: payment-service

  order-record-written:
    matches:
      boundary: postgres
      operation: INSERT
      target: orders
      serviceId: checkout-service
```

The catalog explains how evidence is normalized. It does not declare that checkout must send a payment request or write
an order. A person approves those claims as part of the behavioral contract.

## The Behavioral Contract Gives Effects Meaning

An effect records what Blackbox observed. A claim states what the behavioral contract requires for one case. The catalog
cannot promote an observed payment request into a requirement, and a trace cannot silently change the approved limit.

Blackbox evaluates the claim against sealed evidence. The same behavioral contract, analysis rules, and evidence produce
the same deterministic finding.
