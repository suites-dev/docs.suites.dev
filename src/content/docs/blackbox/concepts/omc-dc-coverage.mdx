**Observable Decision Coverage (ODC)** combines branch-coverage evidence with runtime effect evidence. Branch coverage shows which decision outcomes executed. Effect evidence shows what each execution did at the system boundary.

ODC asks whether the exercised outcomes were associated with distinguishable effects.

```ts title="Illustrative pseudocode"
if (subscriptionRenewal) {
  updateSubscriptionInPostgres();
  refreshSubscriptionInRedis();
} else {
  requestInitialChargeFromStripe();
  publishSubscriptionCreatedToSqs();
}
```

Consider two accepted cases for this decision:

| Case             | Decision outcome | Projected effects                       |
| ---------------- | ---------------- | --------------------------------------- |
| Renewal          | `true`           | PostgreSQL update + Redis refresh       |
| New subscription | `false`          | Stripe charge request + SQS publication |

Here, `subscriptionRenewal` is the varying dimension. Inputs such as plan and region remain controlled. The branch is the decision scope, and the four listed boundary effects form the effect projection.

If both executions are eligible, different effect signatures establish an ODC association. If both outcomes execute but produce the same projected signature, branch coverage may pass while the ODC association is not established.

## Compare Declared Cases

A person approves the comparison before execution. It names:

- the exact member cases;
- the dimension that should vary;
- the dimensions that must remain controlled;
- the decision scope;
- the effects included in the comparison.

ODC cannot infer convenient members from test titles, flow membership, execution order, retries, or observed similarity.

## Missing Evidence Makes ODC Unavailable

Every member needs its own eligible attempt, capture session, decision evidence, and effect evidence. The comparison also needs verified controls and exact source identity.

**Exact source identity** ties decision evidence to the declared decision in the executed artifact, not to a similar title or nearby location. Evidence is **confounded** when required controls differ or remain unknown, so Blackbox cannot attribute an effect difference to the declared varying dimension.

Missing, incomplete, foreign, or confounded evidence cannot become “no difference.” It makes the ODC comparison unavailable.

## Association Is Not Causation

ODC asks whether declared decision outcomes were associated with different projected effect signatures. Other behavior in either execution may contribute to that difference.

ODC does not claim behavioral correctness, causal proof, MC/DC, or OMC/DC compliance.

## Effect Findings Stay Unchanged

Each case receives its ordinary integrity and effect findings first. ODC runs as a separate analysis afterward.

Whether an association is established, not established, or unavailable, ODC cannot erase, rewrite, or strengthen those findings.

## Advanced: OMC/DC Lineage

Observable Decision Coverage takes inspiration from the observability question behind **Observable Modified Condition/Decision Coverage (OMC/DC)**. OMC/DC strengthens structural coverage by asking whether a tested decision's influence remains visible at a monitored oracle variable.

Blackbox applies that question at the system boundary:

| Criterion           | Question                                                                             |
| ------------------- | ------------------------------------------------------------------------------------ |
| **Branch coverage** | Did each decision outcome execute?                                                   |
| **MC/DC**           | Did each atomic condition independently affect its decision?                         |
| **OMC/DC**          | Did that structural obligation remain observable at the monitored oracle?            |
| **Blackbox ODC**    | Were declared decision outcomes associated with different projected runtime effects? |

Blackbox ODC does not implement the formal MC/DC independence obligation or the OMC/DC path obligation. It carries their observability motivation into system and E2E verification.
