**Observable decision coverage (ODC)** asks whether different outcomes of an exercised decision produced distinguishable runtime effects.

ODC is language-neutral. A language capture implementation contributes canonical decision definitions, source locations, source maps, arm hits, and observed effects to the sealed bundle. `@suites/blackbox-coverage-odc` analyzes those records offline.

## From OMC/DC to Blackbox ODC

Blackbox ODC is inspired by the observability problem behind **Observable Modified Condition/Decision Coverage (OMC/DC)**. The original OMC/DC work strengthened MC/DC with a propagation requirement: exercising a structural obligation is not enough when its influence becomes masked before reaching a variable monitored by the test oracle.

Blackbox applies that question at a different level:

| Criterion        | What it asks                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------- |
| Branch coverage  | Did each decision outcome execute?                                                            |
| MC/DC            | Did each atomic condition independently affect its decision?                                  |
| OMC/DC           | Did the MC/DC obligation remain observable along a path to a monitored oracle variable?       |
| **Blackbox ODC** | Did exercised decision outcomes produce distinguishable attempt-scoped runtime effect traces? |

Blackbox ODC is therefore **not** a claim of MC/DC or OMC/DC compliance. It does not prove atomic-condition independence or the formal OMC/DC path obligation. It adapts their observability motivation to system tests, where database, HTTP, cache, and messaging effects form the monitored evidence.

## What ODC Asks

Consider a decision that rejects an unknown subscriber before downstream work:

```ts
if (!user) {
  return reply.status(404).send({ error: "User not found" });
}

await createSubscription(user);
```

Ordinary branch coverage can show that tests executed both outcomes. ODC asks whether those outcomes left distinguishable captured evidence.

| Verdict             | Meaning                                                                 |
| ------------------- | ----------------------------------------------------------------------- |
| `propagating`       | Compared outcomes produced distinguishable canonical evidence           |
| `masking-candidate` | Both outcomes ran, but their evidence signatures were indistinguishable |
| `coverage-gap`      | The bundle contains evidence for only part of the decision              |
| `undecidable`       | The available evidence cannot support a sound comparison                |
| `multi-arm`         | The current binary comparison does not cover the decision shape         |

These are evidence classifications, not causal proof. Other behavior in the compared attempts can also affect the signatures.

## Read One Concrete Comparison

For the decision above, suppose the two complete attempts produce these normalized signatures:

| Outcome      | Normalized evidence                                      |
| ------------ | -------------------------------------------------------- |
| User exists  | `postgres SELECT users`, `postgres INSERT subscriptions` |
| User missing | `postgres SELECT users`                                  |

The `INSERT subscriptions` observation distinguishes the exercised outcomes, so the decision is `propagating`. If both rows contained only `postgres SELECT users`, the result would be `masking-candidate`.

ODC uses the full evidence signatures, including valid observations that are not listed in the effect contract. This makes ODC causally legible without turning every observation into required policy.

## ODC Is Not Effect Coverage

- **Effect analysis** evaluates reviewed required and forbidden behavior.
- **ODC** compares evidence associated with decision outcomes.
- **MC/DC** requires atomic-condition independence that ODC does not claim.

ODC does not read effect contracts to decide whether an arm is correct. It uses canonical decisions and captured evidence from the sealed bundle.

## Research Lineage

- [Modified condition/decision coverage](https://en.wikipedia.org/wiki/Modified_condition/decision_coverage) is an accessible primer on the MC/DC condition-independence requirement and its common variants.
- Whalen, Gay, You, Heimdahl, and Staats introduced OMC/DC in the 2013 paper [Observable Modified Condition/Decision Coverage](https://greg4cr.github.io/pdf/13omcdc.pdf).
- Meng, Gay, and Whalen generalized the observability idea beyond MC/DC in [Ensuring the Observability of Structural Test Obligations](https://greg4cr.github.io/pdf/18omcdc.pdf), covering observable forms of branch, condition, decision, and MC/DC coverage.

These works define MC/DC and OMC/DC. They motivate Blackbox ODC, but they do not specify Blackbox's effect-signature comparison.

## Default Reporting and Explicit Gates

ODC runs by default when the bundle contains the required decision capability. Its findings are report-only unless a team explicitly enables an ODC gate.

Effect contract failures and capture-integrity failures still fail independently of ODC policy.
