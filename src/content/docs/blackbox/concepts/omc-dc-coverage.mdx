:::note Alpha Capability
Observable Decision Coverage is optional per run. It remains separate from ordinary effect findings and cannot change them.
:::

**Observable Decision Coverage (ODC)** combines evidence that code decisions executed with the runtime effects observed for each outcome. It asks whether important outcomes remain distinguishable at system boundaries.

```ts title="Illustrative decision"
if (subscriptionRenewal) {
  updateSubscriptionInPostgres();
  refreshSubscriptionInRedis();
} else {
  requestInitialChargeFromStripe();
  publishSubscriptionCreatedToSqs();
}
```

Two declared contract cases exercise the outcomes:

| Case             | Decision outcome | Observed effect projection         |
| ---------------- | ---------------- | ---------------------------------- |
| Renewal          | `true`           | Postgres update and Redis refresh  |
| New subscription | `false`          | Stripe request and SQS publication |

## Compare Outcomes With Their Visible Consequences

Branch coverage can show that both sides of the decision executed. ODC adds a different question: did each outcome produce a distinguishable pattern at the system boundaries the comparison observes?

The comparison must still come from declared cases. Blackbox does not assemble a convenient comparison from test names, timing, or observed similarity.

## ODC Adds Diagnosis, Not a Verdict

ODC runs after ordinary effect analysis and adds diagnostic insight about the relationship between decisions and effects. A case keeps its ordinary effect finding regardless of whether ODC runs or what ODC reports.

[Look up the exact ODC inputs, availability states, and classifications](/docs/blackbox/reference/observable-decision-coverage).

## Association Is Not Causation

ODC reports an association between executed decision outcomes and projected runtime effects. It does not claim causal proof or behavioral correctness.

### Advanced: OMC/DC Lineage

ODC takes inspiration from the observability question behind **Observable Modified Condition/Decision Coverage (OMC/DC)**.

| Criterion       | Question                                                                  |
| --------------- | ------------------------------------------------------------------------- |
| Branch coverage | Did each decision outcome execute?                                        |
| MC/DC           | Did each atomic condition independently affect its decision?              |
| OMC/DC          | Did that structural obligation remain observable at the monitored oracle? |
| Blackbox ODC    | Were declared outcomes associated with distinct runtime effect patterns?  |

Blackbox ODC does not implement formal MC/DC independence or the OMC/DC path obligation.
