Imagine a system where two product reads both return `200`, so the E2E test passes. The product service still queries Postgres twice instead of using Redis after the first read.

```text
Native system-test result       Blackbox effect finding
─────────────────────────       ─────────────────────────
2 responses returned 200        Postgres SELECT observed 2 times
PASS                            upper bound: at most 1
                                VIOLATED
```

The two results answer different questions:

- **Native assertions** check the visible result produced by the selected system or E2E test.
- **Blackbox findings** check approved system-effect claims against eligible runtime evidence from that same attempt.

## Keep Both Results

Neither result rewrites the other. A failed native assertion does not erase captured runtime facts. A violated effect claim does not change the native test result.

The combined result lets people and coding agents distinguish an output failure from behavior behind a successful output.

## Keep Assurance Bounded

Blackbox evaluates one declared case attempt within its admitted observation capabilities and exact claim scope. It does not claim that every possible transport was observed or that one passing attempt proves all future executions.

Unsupported capability, incomplete evidence, and integrity failure remain explicit outcomes. They never become a pass.
