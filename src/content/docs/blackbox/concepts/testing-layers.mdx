Imagine checkout returns `201`, so the E2E test passes. The running system still sends two payment requests for the
same completed order.

```text
Native system-test result       Blackbox effect finding
─────────────────────────       ─────────────────────────
response returned 201           POST /payments/charges observed 2 times
PASS                            upper bound: at most 1
                                VIOLATED
```

The two results answer different questions:

- **Native assertions** check the visible result produced by the selected system or E2E test.
- **Blackbox findings** check the behavioral contract's runtime-effect claims against evidence from that same attempt.

## The Two Results Protect Different Boundaries

Neither result rewrites the other. A failed native assertion does not erase captured runtime facts. A violated effect claim does not change the native test result.

The combined result lets people and coding agents distinguish an output failure from runtime behavior behind a
successful output.

## One Run Cannot Prove Everything

Blackbox evaluates one declared contract case within the supported observation capabilities and exact claim scope. It
does not claim that every possible transport was observed or that one passing attempt establishes all future executions.

When the evidence cannot support a conclusion, Blackbox preserves that limitation instead of turning uncertainty into a pass.
