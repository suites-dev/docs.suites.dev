A product-cache case declares that two reads succeed and produce at most one Postgres read. Blackbox keeps that meaning separate from the Playwright code that performs the two requests.

## Three Artifacts, Three Responsibilities

| Artifact         | Owns                                                                                         | Must not own                                                              |
| ---------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **SuitePlan**    | Accepted cases, claims, completion requirements, capabilities, topology, and artifact policy | Workers, live endpoints, secrets, runtime identities, or capture outcomes |
| **RunnerBundle** | Exact discovery and concrete realization of selected cases in a runner                       | New meaning, silent exclusions, or runtime-created facts                  |
| **RunPlan**      | Selection, execution units, projects, retry policy, placement, and required capabilities     | New relations, physical evidence, or admission outcomes                   |

Gherkin-linked authoring and direct behavioral declarations both converge on SuitePlan. Equivalent inputs produce equivalent accepted meaning.

## Playwright Realization

For the accepted Playwright target, the generated suite directory contains exactly:

```text
suite.spec.ts
suite.runtime.ts
suite.d.ts
plan.json
```

RunPlan is an in-memory selection, not a fifth generated file.

Exactly one discovered Playwright test binds each selected case. Missing, duplicate, ambiguous, stale, or redirected bindings fail before Blackbox allocates the application sandbox.

## Identity Does Not Come From Labels

Blackbox uses explicit stable identities for flows, requirements, cases, claims, and execution units. Runtime then creates fresh physical identities for each attempt, capture window, capture session, participant, service instance, process, and isolate.

Titles, paths, line numbers, worker IDs, trace IDs, timestamps, and matching text do not replace those identities.

| Identity layer | Example responsibility                           |
| -------------- | ------------------------------------------------ |
| Semantic       | Which accepted case and claim this is            |
| Realization    | Which exact runner relation realizes it          |
| Selection      | Which declared realization this run selected     |
| Runtime        | Which physical attempt and participants executed |
| Evidence       | Which sealed facts belong to that attempt        |

## Keep Authority Directional

Downstream artifacts preserve exact roots and declared relations. Runtime instrumentation observes work but does not evaluate claims. Analysis evaluates sealed evidence but does not connect to or mutate the running system.

Observed effects can test approved meaning. They cannot create it.
