Start with the first layer that could not produce a trusted result. Do not change accepted behavior until you know whether the failure came from identity, execution, capture, integrity, or analysis.

## Choose the Symptom

| Symptom                                                 | Start with                                                                       |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Flow identity or Gherkin no longer matches the suite    | [Feature Drift](/docs/blackbox/troubleshooting/feature-drift)                    |
| A runtime bundle is empty or incomplete                 | [Empty or Incomplete Capture](/docs/blackbox/troubleshooting/no-spans-captured)  |
| The capture cell cannot start or become ready           | [Capture Cell and Sidecar](/docs/blackbox/troubleshooting/docker-and-testbed)    |
| An effect is missing, forbidden, unknown, or mismatched | [Effect Contract Failures](/docs/blackbox/troubleshooting/catalog-failures)      |
| You need a minimal diagnostic package                   | [Collect Diagnostics](/docs/blackbox/troubleshooting/diagnostics-and-debug-logs) |
| You have a reproducible product defect                  | [Report a Bug](/docs/blackbox/troubleshooting/reporting-a-bug)                   |

## Start With Static Identity

```bash
pnpm exec blackbox suites discover e2e/tests --json
pnpm exec blackbox suites check e2e/tests --json
```

Resolve missing, duplicate, or conflicting flow IDs before debugging runtime evidence.

## Diagnose the Runtime in Order

1. Confirm the runner selected the intended flow tag.
2. Confirm the capture cell reached ready state.
3. Confirm test identity reached the SUT through W3C baggage.
4. Verify bundle capabilities and integrity.
5. Inspect effect and ODC analysis separately.
