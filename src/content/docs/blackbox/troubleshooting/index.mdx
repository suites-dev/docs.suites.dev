Start with the earliest boundary that failed. Do not change approved intent until you know whether the problem belongs to alignment, realization, runtime capture, evidence integrity, or analysis.

## Choose the Symptom

| Symptom                                                                         | Start with                                                                           |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Gherkin and the executable suite no longer align                                | [Gherkin and Suite Alignment Failures](/docs/blackbox/troubleshooting/feature-drift) |
| An attempt has no eligible evidence or incomplete capture                       | [Empty or Incomplete Capture](/docs/blackbox/troubleshooting/no-spans-captured)      |
| The testbed cannot start, isolate, or ready the system                          | [Capture Cell and Testbed](/docs/blackbox/troubleshooting/docker-and-testbed)        |
| An effect claim is violated, inconclusive, unsupported, or blocked by integrity | [Effect Claim Failures](/docs/blackbox/troubleshooting/catalog-failures)             |
| You need one reproducible diagnostic chain                                      | [Collect Diagnostics](/docs/blackbox/troubleshooting/diagnostics-and-debug-logs)     |
| You have reduced the problem to a product defect                                | [Report a Bug](/docs/blackbox/troubleshooting/reporting-a-bug)                       |

## Follow the Verification Chain

1. Confirm approved Gherkin compiled and every selected case has one exact realization.
2. Confirm the RunPlan selected only declared cases and a declared RunnerBundle.
3. Confirm Runtime opened fresh capture and admitted the required participants and capabilities.
4. Confirm relevant work correlated, completed, settled, drained, closed, and sealed.
5. Read integrity, native test, effect, and optional ODC findings separately.

A later stage cannot repair an earlier authority or identity failure. Start a fresh runtime attempt after an alignment, implementation, lifecycle, or capture repair.
