Blackbox has an accepted product contract for the Alpha target. That contract defines the behavior the product must deliver, but it does not make every runtime, setup path, or integration publicly supported.

## How Support Becomes Public

Each capability moves through the same promotion sequence:

1. Experiment.
2. Accepted fixture or contract.
3. Falsification.
4. Package.
5. Packed external consumer.
6. Real package-boundary end-to-end verification.
7. Full regression.

A capability is advertised only after all seven stages pass for its exact tested cell. A nearby runtime, library version, topology, or provider does not inherit support automatically.

## Accepted Product Boundary

| Area              | Accepted Alpha target                                                  |
| ----------------- | ---------------------------------------------------------------------- |
| Runner            | Playwright                                                             |
| Application setup | Current Docker Compose project                                         |
| Authoring         | A human-approved behavioral contract in Gherkin or direct declarations |
| Runtime assurance | Fresh attempt-scoped evidence and five deterministic claim verdicts    |
| Effect families   | HTTP, Postgres, Redis, and SQS                                         |
| Decision insight  | Optional-per-run Observable Decision Coverage                          |

The certified language adapter must be named before its support is advertised.

## Application Setup Status

| Setup input                                 | Status           | Boundary                                                                               |
| ------------------------------------------- | ---------------- | -------------------------------------------------------------------------------------- |
| Current development Compose project         | **Alpha target** | Uses the project's declared topology.                                                  |
| Testcontainers topology                     | **Experimental** | The intended lifecycle is documented, but no public integration interface is promised. |
| Dockerfile and build context                | **Planned**      | Requires certification as its own setup and isolation cell.                            |
| Distribution artifacts and project launcher | **Planned**      | Requires certification as its own process and artifact cell.                           |

Experimental and planned paths are not equivalent to the Alpha Compose path. Blackbox does not silently fall back to another setup or weaken an evidence boundary.

The setup guides may use conceptual pseudocode to show the intended workflow. That pseudocode is not a public API or a support claim.
