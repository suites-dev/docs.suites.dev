## What You Proved

The ordinary test assertion still proves the public result. The Blackbox result now also proves that the selected required effects appeared and the selected forbidden effects did not.

That is enough for a first run. Do not baseline the entire suite yet. Add the next flow only after the first catalog diff is understandable in review.

## Connect Intent Next

Runtime effects work independently of a specification format. When the team wants to connect the proof to written intent, continue with [Connect Specifications to Runtime Evidence](/docs/blackbox/quickstart/connect-specifications-to-runtime-evidence).

That page offers two optional paths:

- bind EARS requirement IDs to the flow and compute requirement verdicts;
- emit Gherkin from the executable test and check the readable behavior for drift.

For the artifact formats behind this quickstart, use the [Reference hub](/docs/blackbox/reference).
