The behavior-alignment loop produced one accepted `subscribe-user` flow. Now run that flow against the system under test and inspect what actually happened.

An **effect** is a meaningful action at a system boundary, such as reading a database row, calling another API, changing a cache, or publishing a message.

## 1. Run the Accepted Flow

```bash
pnpm run db:test:reset
pnpm exec blackbox test --flow subscribe-user
```

Blackbox performs one runtime lifecycle:

```text
create cell → start application → run Playwright attempts → settle capture
    → seal evidence → analyze observed effects and decisions → report
```

No effect contract has been accepted yet, so Blackbox records facts without treating them as required or forbidden policy.

```text
FLOW subscribe-user
  tests       PASS         2 attempts
  integrity   PASS         capture complete
  effects     NOT CHECKED  no accepted contract
  ODC         REPORT       available for review in Step 4
```

## 2. Confirm the Evidence Is Trustworthy

Do not interpret absent effects or ODC when integrity is inconclusive. For this run, `integrity PASS` means the expected capture service became ready, both attempts settled, required artifacts were present, and their identities and digests passed validation.

This is the first important milestone:

```text
FIRST TRUSTWORTHY RUNTIME EVIDENCE
tests PASS + integrity PASS
```

The native assertions still answer only what the client observed. The sealed evidence can now answer what the application did behind those responses.

## 3. Inspect the Same Run Offline

```bash
pnpm exec blackbox analyze --run latest
```

`blackbox analyze` does not restart the application. With no accepted effect policy, it prints the observations grouped by attempt:

```text
ATTEMPT known-user
  postgres SELECT users                 service=api
  postgres INSERT subscriptions         service=api

ATTEMPT unknown-user
  postgres SELECT users                 service=api
```

The unknown-user attempt also contains no payment-provider request. That absence becomes a conclusive negative fact only because integrity and the configured isolation assurance passed.

## 4. Keep Observation and Policy Separate

The subscription insert is an observed fact from one attempt. The missing payment call is another fact. Neither becomes accepted behavior merely because the runtime produced it.

Ask:

- Which actions must always happen for this flow?
- Which actions must never happen?
- Which differences merely help explain the two decision outcomes?

The next step turns the reviewed answers into policy. The sealed evidence remains unchanged.

For the complete artifact layout and integrity fields, see [Runtime Evidence and Integrity](/docs/blackbox/concepts/runtime-evidence). If decision attribution is missing, use [Source Maps and Service Layouts](/docs/blackbox/guides/source-maps-and-service-layouts).

## Result

You have one immutable run with passing tests, passing integrity, and attempt-specific observed effects. No observation has silently become policy.
