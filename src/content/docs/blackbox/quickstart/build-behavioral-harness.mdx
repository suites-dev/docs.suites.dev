Use this guide when a Playwright system or E2E test already exercises the flow you want Blackbox to verify.

## Before You Begin

You need:

- One existing Playwright test.
- One product requirement a person can review.
- OpenTelemetry coverage for the runtime effects that matter to the requirement.

## 1. Start With the Visible Result

```ts title="tests/checkout.e2e.spec.ts"
import { expect, test } from "@playwright/test";

test("completes checkout", async ({ request }) => {
  const response = await request.post("/checkout", {
    data: { cartId: "cart-42" },
  });

  expect(response.status()).toBe(201);
});
```

This test establishes the visible result. It does not tell you whether the running system requested payment twice.

## 2. Approve the Behavioral Contract

A person reviews the product requirement and approves the expected behavior for this flow:

- Checkout returns `201`.
- A completed checkout sends at most one payment charge request.

Gherkin is the primary authoring example, but it is optional. A project may use direct behavioral declarations instead.

## 3. Validate the Contract

Validate the behavioral contract before connecting it to the existing test.

```text title="Conceptual pseudocode"
<validate behavioral contract>
```

Use the command published for the installed Blackbox distribution. The placeholder above is not CLI syntax.

## 4. Connect the Test

Use the generated typed binding surface to connect the approved contract case to the Playwright actions and native assertion. The existing test realizes the contract but does not become its authority.

```text title="Conceptual pseudocode"
behavioral contract
  -> generated typed binding
  -> existing Playwright test
```

Validate that the selected contract case resolves to exactly one runnable test.

## 5. Run With Blackbox

Continue with [Choose How Blackbox Runs Your Application](/docs/blackbox/guides/set-up-the-testbed). Blackbox will run the selected test, capture fresh runtime evidence, and evaluate its effect claims.
