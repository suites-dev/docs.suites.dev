In this tutorial, you will connect one checkout behavioral contract to a Playwright test, run it against a Compose system, and read the native result beside its Blackbox finding.

## Before You Begin

Complete [Installation](/docs/blackbox/quickstart/installation). Use a project that runs system or E2E tests with Playwright and starts the application with Docker Compose.

The example requirement is simple: a completed checkout charges the customer once.

## 1. Choose an Authoring Mode

Blackbox accepts a behavioral contract through reviewed Gherkin or direct behavioral declarations. These docs show Gherkin as the primary path:

```gherkin title="features/checkout.feature"
Feature: Checkout completion
  Scenario: Charge a completed checkout once
    When checkout completes
    Then the response status is 201
    And no more than one charge request is sent
```

A coding agent can propose this contract from the product requirement. A person reviews and approves it before implementation continues.

## 2. Validate the Behavioral Contract


## 3. Complete the System Test

Use the generated typed binding to complete the Playwright actions and visible assertion:

```ts title="checkout.e2e.spec.ts"
import { expect, test } from "@playwright/test";

test("completes checkout", async ({ request }) => {
  const response = await request.post("/checkout", {
    data: { cartId: "cart-42" },
  });

  expect(response.status()).toBe(201);
});
```

The Playwright assertion verifies the visible response. The behavioral contract also limits the payment effect that the running system may produce.

## 4. Connect the Compose System

```yaml title="compose.yaml, shortened"
services:
  checkout-service:
    build: ./services/checkout
    depends_on: [payment-service, postgres]
  payment-service:
    build: ./services/payment
  postgres:
    image: postgres
```

Make every service and dependency the test can reach explicit. Continue with [Use an Existing Compose Project](/docs/blackbox/guides/use-existing-compose) for the full boundary checklist.

## 5. Run the Contract Case

```text title="Conceptual pseudocode"
<run checkout-completion with Blackbox>
```

The system test and Blackbox return separate results from the same attempt:

```text
System test       passed: checkout returned 201
Blackbox finding  violated: POST /payments/charges, maximum 1, observed 2
```

The visible assertion passed, but the runtime effects did not satisfy the behavioral contract.

## 6. Repair and Verify Again

Ask the coding agent to remove the duplicate payment request without changing the behavioral contract. Then run a fresh attempt.

```text
System test       passed: checkout returned 201
Blackbox finding  satisfied: POST /payments/charges, maximum 1, observed 1
```

## What You Completed

- Approved one behavioral contract.
- Realized it as a Playwright system test.
- Ran it against a Compose topology.
- Read the native assertion and runtime-effect finding separately.
- Verified a repair with fresh evidence.
