Complete one trustworthy Blackbox flow in four steps. You will keep or create one Playwright system test, connect the application, inspect what it did, and turn the accepted behavior into deterministic verdicts.

This Quickstart uses a compiled Node.js and TypeScript application started with a host command. The flow runs serially against dedicated test data so the first setup is easy to reason about.

## Before You Start

You need:

- A Node.js project using pnpm and Playwright, or a project where you can add Playwright.
- An application that builds to executable JavaScript with source maps.
- A test database or equivalent mutable state that is safe to reset.
- One application behavior worth protecting.

## Choose Your Starting Point

| Your situation                                  | Start here                                                                                                                               |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **I already have a passing system or E2E test** | [Step 1A: Start From an Existing Test](/docs/blackbox/quickstart/build-behavioral-harness) keeps the test and gives it a stable flow ID. |
| **I do not have a system or E2E test yet**      | [Step 1B: Start Without a Test](/docs/blackbox/guides/turn-requirements-into-system-test) creates a tagged test shell from one behavior. |

Both routes reach the same checkpoint before runtime capture: one passing Playwright flow with exactly one stable `@flow:<id>`.

## Follow the Four Steps

1. **Get one accepted system flow.** Keep a passing test in [Step 1A](/docs/blackbox/quickstart/build-behavioral-harness), or create its shell from plain-language intent in [Step 1B](/docs/blackbox/guides/turn-requirements-into-system-test).
2. **[Connect your application](/docs/blackbox/quickstart/add-to-existing-test).** Tell Blackbox how to start the system under test, add the Playwright fixture, and make the native flow pass.
3. **[Run and inspect evidence](/docs/blackbox/quickstart/add-runtime-evidence).** Run the flow, inspect its captured effects, and approve only the runtime actions that should become policy.
4. **[Enforce effects and read ODC](/docs/blackbox/quickstart/enforce-runtime-effects).** Apply the policy to sealed evidence, read the separate verdicts, and repair the implementation without redefining success.

## What Success Looks Like

```text
FLOW subscribe-user
  tests       PASS    2 attempts
  integrity   PASS    capture complete
  effects     PASS    required and forbidden policy satisfied
  ODC         REPORT  user-exists outcomes produced distinct evidence
```

At that point, the visible response, evidence integrity, required and forbidden runtime actions, and decision propagation are separate results. The same flow can become a CI gate.

## If Your Application Starts Differently

Finish Step 1 first. Then use [Choose How Blackbox Runs Your Application](/docs/blackbox/guides/set-up-the-testbed) to replace only the host-command portion of Step 2 with Compose, a Dockerfile, compiled artifacts, an external process, or a custom provisioner.
