Complete both Blackbox loops with one subscription behavior. First align readable intent with an executable Playwright flow. Then run that flow against the application, inspect its evidence, and compute separate runtime verdicts.

```text
Behavior alignment:    human-readable behavior ↔ @flow system test
Runtime verification:  @flow system test → SUT → evidence → verdicts → repair
```

This Quickstart uses Gherkin so you can experience the complete alignment loop. Gherkin remains optional during runtime execution.

The runtime example uses a compiled Node.js and TypeScript application started with a host command. It runs serially against dedicated test data so the first setup is easy to reason about.

## Before You Start

You need:

- A Node.js project using pnpm and Playwright, or a project where you can add Playwright.
- An application that builds to executable JavaScript with source maps.
- A test database or equivalent mutable state that is safe to reset.
- One application behavior worth protecting.

## Choose Your Starting Point

| Your situation                                  | Start here                                                                                                                                                             |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **I already have a passing system or E2E test** | [Step 1A: Start From an Existing Test](/docs/blackbox/quickstart/build-behavioral-harness) keeps it, assigns a stable flow ID, and emits readable behavior for review. |
| **I do not have a system or E2E test yet**      | [Step 1B: Start Without a Test](/docs/blackbox/quickstart/start-without-test) turns one reviewed behavior into the same tagged Playwright flow.                        |

Both routes produce the same artifacts:

```text
e2e/features/subscribe-user.feature
e2e/subscribe-user.system.test.ts
@flow:subscribe-user
```

Before runtime capture, the Playwright flow must pass.

## Follow the Four Steps

1. **Align one readable behavior and executable flow.** Start from a passing test in [Step 1A](/docs/blackbox/quickstart/build-behavioral-harness), or from human intent in [Step 1B](/docs/blackbox/quickstart/start-without-test). Review the Gherkin and keep one stable flow ID across both artifacts.
2. **[Connect your application](/docs/blackbox/quickstart/add-to-existing-test).** Tell Blackbox how to start the system under test, add the Playwright fixture, and make the native flow pass.
3. **[Run and inspect evidence](/docs/blackbox/quickstart/add-runtime-evidence).** Run the accepted flow and inspect the effects and decision evidence it produced. Observations are facts, not policy.
4. **[Approve effects and read ODC](/docs/blackbox/quickstart/enforce-runtime-effects).** Approve the smallest effect policy, analyze the sealed evidence, and repair implementation without redefining success.

## What Success Looks Like

```text
FLOW subscribe-user
  tests       PASS    2 attempts
  integrity   PASS    capture complete
  effects     PASS    required and forbidden policy satisfied
  ODC         REPORT  user-exists outcomes produced distinct evidence
```

At that point, readable intent, native assertions, evidence integrity, effect policy, and decision propagation remain separate but connected by one stable flow identity.

## If Your Application Starts Differently

Finish Step 1 first. Then use [Choose How Blackbox Runs Your Application](/docs/blackbox/guides/set-up-the-testbed) to replace only the host-command portion of Step 2 with Compose, a Dockerfile, compiled artifacts, an external process, or a custom provisioner.
