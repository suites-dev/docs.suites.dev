Complete both Blackbox loops with one subscription behavior. First align readable intent with an executable Playwright flow. Then run that flow against the application, inspect its evidence, and compute separate runtime verdicts.

```text
Alignment:     approved Gherkin -> generated contracts -> project suite
Verification:  project suite -> running system -> evidence -> findings -> repair
```

The Alpha workflow uses approved Gherkin to preserve human intent before runtime execution. Gherkin guides the realization; it does not become runtime evidence or change an effect finding.

The runtime example uses a compiled Node.js and TypeScript application started with a host command. It runs serially against dedicated test data so the first setup is easy to reason about.

## Before You Start

You need:

- A Node.js project using pnpm and Playwright, or a project where you can add Playwright.
- An application that builds to executable JavaScript with source maps.
- A test database or equivalent mutable state that is safe to reset.
- One application behavior worth protecting.

## Choose Your Starting Point

| Your situation                                  | Start here                                                                                                                                                      |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **I already have a passing system or E2E test** | [Step 1A: Start From an Existing Test](/docs/blackbox/quickstart/build-behavioral-harness) keeps it, recovers a Gherkin proposal, and aligns the approved case. |
| **I do not have a system or E2E test yet**      | [Step 1B: Start Without a Test](/docs/blackbox/quickstart/start-without-test) starts from approved Gherkin and implements its executable realization.           |

Both routes establish the same artifact chain:

```text
approved Gherkin
  -> SuitePlan and generated binding contracts
  -> project-owned Playwright suite
  -> RunnerBundle and selectable RunPlan
```

Before runtime capture, the Playwright flow must pass.

## Follow the Four Steps

1. **Align one readable behavior and executable flow.** Start from a passing test in [Step 1A](/docs/blackbox/quickstart/build-behavioral-harness), or from human intent in [Step 1B](/docs/blackbox/quickstart/start-without-test). Review the Gherkin and close every binding gate before runtime.
2. **[Connect your application](/docs/blackbox/quickstart/add-to-existing-test).** Tell Blackbox how to start the system under test, add the Playwright fixture, and make the native flow pass.
3. **[Run and inspect evidence](/docs/blackbox/quickstart/add-runtime-evidence).** Run the accepted flow and inspect the effects and decision evidence it produced. Observations are facts, not policy.
4. **[Approve effect claims and read findings](/docs/blackbox/quickstart/enforce-runtime-effects).** Approve the smallest consequential claims, analyze the sealed evidence, and repair implementation without redefining success.

## What Success Looks Like

The walkthrough is complete when the accepted Gherkin and executable suite align, the native test passes, evidence is eligible, and each effect claim has a bounded finding. Optional ODC remains a separate result.

## If Your Application Starts Differently

Finish Step 1 first. Then use [Choose How Blackbox Runs Your Application](/docs/blackbox/guides/set-up-the-testbed) to replace only the host-command portion of Step 2 with Compose, a Dockerfile, compiled artifacts, an external process, or a custom provisioner.
