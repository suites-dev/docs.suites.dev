This page is the short path into the runnable Quickstart. It uses one Playwright flow in your project, so every command runs against a **system under test (SUT)**—the application and services—and fixture data you already trust.

```text
request -> system -> successful response
                  \
                   -> forbidden payment call
```

## Start in Your Playwright Project

```bash
cd path/to/your-playwright-project
pnpm add -D @suites/blackbox @suites/blackbox-cli @playwright/test
```

This page does not depend on a separate example checkout. The Quickstart starts from your existing system test, SUT command, and dedicated-data setup.

An **effect** is a runtime action such as a database write, API call, or published message. **Observable decision coverage (ODC)** compares the effects produced by different outcomes of a code decision.

## Build the Four-Step Example

Follow the Quickstart in order:

1. [Build one behavioral harness](/docs/blackbox/quickstart/build-behavioral-harness).
2. [Connect a host-command SUT](/docs/blackbox/quickstart/add-to-existing-test).
3. [Run and inspect evidence](/docs/blackbox/quickstart/add-runtime-evidence).
4. [Enforce effects and read ODC](/docs/blackbox/quickstart/enforce-runtime-effects).

After Step 2, run the selected flow from the same project directory:

```bash
pnpm run db:test:reset
pnpm exec blackbox test --flow subscribe-user
```

The reset is one-time tutorial setup for a serial, no-retry flow whose attempts use independent fixture keys. If an attempt requires clean database state, run the reset provider before that attempt or recreate its cell.

Expected result after the completed Quickstart:

```text
FLOW subscribe-user
  tests       PASS  2 attempts
  integrity   PASS  capture complete
  effects     PASS  required and forbidden policy satisfied
  ODC         REPORT  user-exists outcomes produced distinct evidence
```

If an implementation regression adds the forbidden payment call, the visible assertion can stay green while the effect verdict changes:

| Signal                 | Normal run | Regression run |
| ---------------------- | ---------- | -------------- |
| Response assertion     | Pass       | Pass           |
| Required user lookup   | Present    | Present        |
| Forbidden payment call | Absent     | Present        |
| Effect verdict         | Pass       | Fail           |

The runner owns the assertion. Node capture observes supported effects. The sidecar seals the evidence, and offline analysis applies the reviewed contract.

## Inspect the Same Run Offline

```bash
pnpm exec blackbox analyze --run latest
```

The analyzer verifies integrity before computing the effect verdict and ODC. It does not restart the demo application.

## Result

You have exercised the same command you can keep in local development and CI. Continue with the [full Quickstart overview](/docs/blackbox/quickstart/) when you need to revisit the artifact layout or choose a different SUT source.
