Write a **solitary test**, where every dependency is mocked, then a **sociable test**, where a selected dependency runs its real implementation.

## Prerequisites

Complete [Installation](/docs/get-started/installation/) with the NestJS adapter and either Jest or Vitest. This walkthrough uses the runner configuration and `suites.d.ts` from that page. Vitest examples assume `globals: true` as shown there.

The same TestBed API works with Inversify and InjectionJS. For framework-specific code, see the [Inversify examples](https://github.com/suites-dev/suites-unit-examples) or follow the [InjectionJS guide](/docs/guides/injectionjs/) for a complete constructor-injection test.

## Step 1: Creating the Application Code

Create these three files under `src/`. The repository returns in-memory data, so the example does not need a database.

```typescript title='src/types.ts'
export interface User {
  id: number;
  name: string;
  email: string;
}
```

### Create a Repository Class

```typescript title='src/user.repository.ts'
import { Injectable } from '@nestjs/common';
import type { User } from './types';

@Injectable()
export class UserRepository {
  async getUserById(id: number): Promise<User> {
    // This example returns in-memory data; it performs no I/O.
    return { id, name: 'John Doe', email: 'john@example.com' };
  }
}
```

### Create a Service Class with a Dependency

```typescript title='src/user.service.ts'
import { Injectable } from '@nestjs/common';
import { UserRepository } from './user.repository';

@Injectable()
export class UserService {
  constructor(private userRepository: UserRepository) {}

  async getUserName(id: number): Promise<string> {
    const user = await this.userRepository.getUserById(id);
    return user.name;
  }
}
```

## Step 2: Writing the First Test with Suites

This example writes a test for a `UserService` that depends on a `UserRepository`:

```typescript title="src/user.service.spec.ts"
import 'reflect-metadata';
import { type Mocked, TestBed } from '@suites/unit';
import { UserService } from './user.service';
import { UserRepository } from './user.repository';

describe('User Service Unit Spec', () => {
  let userService: UserService;
  let userRepository: Mocked<UserRepository>;

  beforeEach(async () => {
    const { unit, unitRef } = await TestBed.solitary(UserService).compile();

    userService = unit;
    userRepository = unitRef.get(UserRepository);
  });

  it('should return the user name and call repository', async () => {
    userRepository.getUserById.mockResolvedValue({
      id: 1,
      name: 'John Doe',
      email: 'john@doe.com',
    });

    const result = await userService.getUserName(1);

    expect(userRepository.getUserById).toHaveBeenCalledWith(1);
    expect(result).toBe('John Doe');
  });
});
```

### Running the Test

Run with the runner configured during installation:

```bash
pnpm exec jest
# OR
pnpm exec vitest run
```

With these files, expect **one passing test**. Jest output looks like this; Vitest formats the result differently:

```
 PASS  src/user.service.spec.ts
  User Service Unit Spec
    ✓ should return the user name and call repository

Tests:  1 passed, 1 total
```

### What Just Happened?

When `TestBed.solitary(UserService).compile()` is called, Suites automatically:

1. **Analyzed** `UserService`'s constructor and discovered its `UserRepository` dependency
2. **Created** a type-safe mock of `UserRepository` with all methods automatically stubbed
3. **Injected** the mock into `UserService` without manual wiring
4. **Provided** type-safe access to both the service (`unit`) and its mocks (`unitRef`)

## Step 3: Keep a Dependency Real

Reuse the same `UserService` and `UserRepository`. In this example, the repository returns in-memory data, so it is safe to execute without a database.

Add a second test file:

```typescript title="src/user.service.sociable.spec.ts"
import 'reflect-metadata';
import { TestBed } from '@suites/unit';
import { UserService } from './user.service';
import { UserRepository } from './user.repository';

describe('User Service Sociable Spec', () => {
  it('returns the name from the real repository', async () => {
    const { unit } = await TestBed.sociable(UserService)
      .expose(UserRepository)
      .compile();

    await expect(unit.getUserName(1)).resolves.toBe('John Doe');
  });
});
```

Run the same test command again. Expect **two passing tests in two files**. The solitary test uses the configured mock; the sociable test calls the repository's real `getUserById()` implementation.

Use `.expose()` only for classes whose real behavior you want to exercise. In a repository that accesses a database, keep the database client mocked. Suites does not intercept direct imports or prevent I/O inside exposed code.

## How TestBed Creates the Test

The NestJS adapter reads the class's dependency metadata. TestBed creates mocks for its dependencies, substitutes the real classes selected with `.expose()`, and constructs the unit. It does not bootstrap a NestJS module or application.
